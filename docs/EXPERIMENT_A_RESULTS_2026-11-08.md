# Gemini 实验 A：最终结果（2026-11-08）

**已完成810/810条正式轨迹。主对照得到正向结果：提供可见行统计检查的完整辅助包，使这批查询上的接受区分度提高 9.4 个百分点，六表描述性区间为 [5.0, 13.3]。**

这是30个已有查询、每查询3份新行样本、六张公共表上的前瞻干预；不是810个独立任务，也不是新表泛化检验。仅Gemini3.8 Flash，无Qwen新运行。

## 主对照：原始行 vs 原始行加检查

| 指标 | raw | check |
|---|---:|---:|
| 正确候选被接受 | 88/90 | 90/90 |
| ×1.10错误候选被接受 | 60/90 | 52/90 |
| ×1.50错误候选被接受 | 25/90 | 20/90 |
| 两类错误候选合计被接受 | 85/180 | 72/180 |
| 错误候选下输出了错误数值答案 | 96/180 | 74/180 |
| 错误候选下有效null／数值弃答 | 63/180 | 98/180 |
| 错误候选下输出正确数值答案 | 0/180 | 0/180 |

主指标是 clean acceptance 减去两类 corrupted acceptance 的均值，再按抽样→查询→表平均。它不是任务准确率。check−raw 为 +9.4pp；clean acceptance 差 +2.2pp，描述性区间 [0.0, 4.4]pp。联合规则满足（区分度下界>0且clean接受损失下界不劣于−5pp），但不构成经功效设计的总体非劣性证明。

strict-valid完整配对敏感性：61份抽样、29查询，区分度 +11.1pp，区间 [2.2, 20.3]pp。它对格式完整情况有条件选择，不替代保留全部分母的主结果。原始无效回复均保留，没有为得分重跑。

人话：给Gemini已有数据行算出的区间/flag，确实让它在这组任务里少接受一些错值，正确值接受没有下降；主要收益是拒绝／弃答，**没有自动把错数字纠正成真值**。检查组仍接受72/180个错误（40.0%），不能称作可靠纠错器。

## 代码组：保留数据，仅作诊断

代码组270条也全部采齐，但有192条来自初版工具、78条来自修复后。额外合成检查发现初版会拒绝NumPy内部子模块，暂停并追加协议后，只续跑未完成单元；修复前554条各组回复按SHA原样保留。主轨迹实际未观察到该特定internal-import错误；不能将普通工具错误归因于它。

按修订的保守规则，C属于混合运行时诊断，不能当作统一、无故障的公平计算对照，更不能据此断言模型不会计算或缺乏核验意愿。C完整计数、两阶段工具错误和来源均在机器可读summary中。没有额外重生C回复。

## 论文可新增的结论

> 在所选30个数值查询、相同可见行条件下，提供基于这些行的统计检查辅助包，改善了Gemini的clean/corrupt接受区分，主要通过增加对错误候选的拒绝和弃答。收益有限，错误采纳仍普遍存在。该结果支持进一步研究可见证据核验辅助，不证明runtime是唯一正确位置、统计内容独立于警告的机制、新表泛化或端到端恢复收益。

当前稿件可用这项新干预取代“runtime有用”仅靠动机推导的部分，但应保留系统层建议与实际已测效果的区别。
