**当前版本的论点确实偏薄。** “多看一些数据，通常更容易识别异常”符合统计常识。增加同类模型数量、继续扩大一张 AUROC 表，或将失败 scorer 换成更大的模型，都需要回答新增知识是什么。值得加强的方向是把研究问题推进到“核验预算有限时，系统如何获取足够证据，并作出有明确范围的决定”。

**最值得开发的方法候选，是按查询特点分配证据预算的核验器。** 用人话说，它收到一个数值后，逐步读取能核对这个数值的数据，证据足够时作决定，预算耗尽时保留判断。

它需要解决三个具体问题。哪些原始数据与当前查询有关，什么时候需要继续读取，以及判断的错误概率如何与额外成本同时报告。潜在方法贡献来自这三件事的联动和实验效果，统计区间采用已有方法。

第一版应限制在无过滤的数值 mean/sum，正确处理缺失值。现有数据有 45 个这样的任务，但只有 28 个不同的“表、运算、列”组合，合并 mean/sum 后有 22 个列级查询族。这些任务可以作为离线可行性材料，扰动版本、抽样重复和等价查询要保留相关结构。

建议接口明确返回 query_id、snapshot_id、总体大小、数值有效域、证据行 ID 和抽样规则。工具返回的候选值先固定，再启动额外抽样。核验器知道当前在审计哪张表的哪个快照、哪个统计量。

可信边界必须具体。第一版假设原始行抽样器与其元数据可靠，查询语义正确，候选聚合工具的返回可能错误。若聚合和证据抽样同时受同一错误控制，两者可一致地返回错误内容，保证的适用范围也随之改变。所有对照方法应获得相同元数据与相同证据权限。

对 mean，设真实目标为 θ，候选返回为 y，任务预先给定允许误差 ε，允许窗口为 T(y)。对 sum，可在有可靠有效行数且语义一致时转换为均值审计。使用已有的有限总体置信序列，构造随样本增加更新的 C_t，并在其假设下满足

```text
P(对所有检查时点 t，θ 都在 C_t 中) ≥ 1 - α
```

核验规则可以明确为三个结果。

1. C_t 完全位于 T(y) 内，放行候选值。
2. C_t 与 T(y) 不相交，标记候选值与证据不符。
3. 两者仍有重叠，继续取证，达到预算后返回证据不足。

ε 是任务允许误差，需在审计前固定。α 控制一次审计中错误决定的概率，需要声明成立条件。放行集合中的条件错误率有不同分母，应另行估计。多次审计组成一个工作流时，也要处理跨返回的错误预算。

原 benchmark 的精确 task_success 仍按原 tolerance 计算。新增的 ε 正确性与精确成功率应分别报告。最简单的核验层可以在放行时继续使用 y，在拦截或证据不足时触发有明确定价的回退或保留判断。

初版的“按查询特点”应具体且克制。mean/sum 使用相应的数值证据与有效行数。后续可为过滤计数采用指示变量，为过滤均值处理分子和分母的不确定性。中位数和最大值需要另外的推断方法或保留判断，不能直接套用均值区间。

对带过滤的查询，优先抽取匹配行可能提高效率，但寻找匹配行、建立索引和执行谓词会消耗资源。返回行数、实际扫描行数、服务器计算与模型 token 成本均需计量。若只把返回行数算作成本，方法可能借助大量隐藏计算得到表面收益。

必须先确认拟研究场景中的核验预算确实受限。现有 CSV 规模下，独立全量重算可能很便宜。只有行读取权限、数据传输或服务计算等限制被明确计量或执行时，样本核验的问题定义才有足够现实意义。若采用接口级行读取上限，应对所有方法一致执行，并将结果范围限定为这个受控设置。若全量可信重算可用且更便宜，方法路线应降级或停止。

已有理论可支持区间，但不保证这个候选方法有实用价值。严谨区间可能在 5% 的轻微污染上非常宽，导致大量保留判断。因此，可行性 pilot 的重要结果也包括它在哪些查询和预算下失去实用性。[有限总体置信序列](https://papers.nips.cc/paper/2020/hash/e96c7de8f6390b1e6c71556e4e0a4959-Abstract.html)

建议的离线实验在六张现有表上比较同一批任务和同一随机证据序列，使用累计预算 5、10、20、50、100、200、500、1000 行，并按总体大小截断。所有方法共享同一最大预算。按表留一验证用于选择分配策略或校准经验阈值，测试表的污染结果不参与调参。

必须纳入下面这些基线。

| 基线 | 它排除的替代解释 |
|---|---|
| 固定 k 随机样本上的现有 0d 和解析统计基线 | 收益是否只是多读了数据 |
| 同样检查时点、预先分配 α 的序贯基线 | 收益是否来自对一个无效反复查看基线的比较 |
| 使用成熟置信序列但采用固定证据分配的基线 | 按查询分配或停止策略是否有额外价值 |
| 简单代数一致性和范围规则 | 收益是否来自遗漏了便宜的确定性检查 |
| 一律重查聚合工具 | 方法是否只在重查本来就失败的设置中有用 |
| 全量可信重算 | 额外证据方案与直接核验的真实成本差 |
| 全部放行与全部保留判断 | 性能是否来自两个没有实用性的极端策略 |

主要端点应同时包含错误候选的放行率、正确候选的误拦截率、正确候选的直接放行率、保留判断率，以及平均和尾部证据成本。检测分数的 AUROC 可作为辅助指标。全量重算和样本核验都应计入服务器工作，当前几百到几万行的表未必使全量重算昂贵。

建议的投入门槛是，在相同错误要求与有用放行率下，证据开销比最佳同权限基线降低约 25%，或者在相同证据开销下检测率提高约 10 个百分点。这些是待作者确认的实用性目标，尚未锁定为预注册判据。若只改善一个表、主要依赖额外权限，或通过大量保留判断取得低错误率，应重新评估方法贡献。

**第二项强化实验，是随机改变错误反馈和后续污染条件。** 它最贴近现有 Gemini 结果，可以把一个相关现象转成可解释的实验。

候选解释之一是，错误反馈促使 agent 追加或改变工具调用，在后续返回可获得正确信息时改善结果。竞争解释是，agent 本来就在继续计算或核验，报错只是其中一段经历。还可能存在预算消耗、数值别名、额外样本或接口语义变化等解释。

主要研究量可定义为两项错误反馈效应的差。

```text
Δ = [成功率(一次错误反馈, 一次投毒) - 成功率(无错误反馈, 一次投毒)]
  - [成功率(一次错误反馈, 持续目标污染) - 成功率(无错误反馈, 持续目标污染)]
```

Δ 的方向和大小目前未知。即使观察到交互，也需要结合实际获得的证据解释，不能直接给出“多少恢复由某个中介造成”的比例。

建议从共享的“任务、初始查询、首次投毒返回”前缀分支，固定输出字段和当前快照。主实验使用受控查询协议，使正常请求可确定执行。首次目标调用由协议固定，评价范围集中于返回后的行为，真实 Python 自由代码环境用于后续外部复现。主实验采用以下四臂，另加两个 clean 初始返回的反馈控制，共六臂。

| 因素 | 条件 |
|---|---|
| 后续污染 | 只污染首次目标返回，或持续污染同一目标统计量 |
| 一次工具错误反馈 | 在首次投毒后的下一次合格工具调用给予预定义 ERROR，或正常执行 |

错误处理应与已有的 Python 环境语义分开。主实验用预定义的一次性错误反馈，分别解释这个干预的总效应。状态持久化、允许的 builtin 和真实 NameError 类型可作为后续环境消融。它们会同时改变多个执行条件。

在分支前分配实验条件。如果 agent 后续没有发起合格调用，仍保留在分配条件的总体中，报告干预实际到达率。这样可避免只挑选“恰好重查”的轨迹后再解释效应。

ERROR 会消耗时间和调用预算。主分析可固定总请求预算，估计这个真实预算内的总效应。辅助对照匹配成功执行机会，检查结果是否主要由预算差造成。两类分析回答不同的问题。

持续目标污染应按规范查询含义定义。完整目标字段及其数值别名都要按同一错误值更新，记录实际投毒与残留正确信息。原始行、替代统计量等额外证据的权限需明示，并在轨迹中记录。持续污染目标统计量时，其他途径仍可能提供正确信息。若研究目标改为正确反证是否存在，就需要另外操纵反证端点的可用性。本项目可以沿用 ToxicBench 的受控字段实验思想，避免将格式差异当成模型能力差异。[ToxicBench](https://arxiv.org/html/2609.37153v1)

输出至少包括按分配条件计算的最终精确成功率、实际投毒率、污染采用率、后续调用数、正确证据出现时点、观察到的针对性核验和错误修复行为。可见识别需按明确标注规则判断，抽样使用两位人工独立复核，保留分歧及裁决记录。恢复与可见识别分别标注。[ReInBench](https://arxiv.org/html/2610.36471v1)

可先固定 30 个去重查询，每张表五个，按任务分块随机化六种分支顺序。每臂先收集一次完成轨迹，得到 180 条 pilot，用来检验操纵、格式和预算。它适合发现较大的设计问题或效应，精确的样本量应依据任务配对方差与想区分的效应范围再确定。举例说，60 个查询、六臂、两次独立完成为 720 条轨迹，但模型重复与任务仍需分层处理。

按上一轮 Gemini 630 条轨迹约 $1.42 的已保存 token 用量，180 条的简单线性估算约 $0.41。新实验会改变轨迹长度，这个数只说明成本数量级。可以先用小样本记录实际 token 和调用数，再形成预算。另一模型家族的复现需要独立计算资源。

这个方向的价值在于操作条件与交互效应。若两种后续污染条件下错误反馈的作用相近，或随机对照显示报错没有稳定增益，那么“报错促成恢复”的候选解释会减弱。已有轨迹仍可说明不同路径的存在，论文应据新实验更新解释。

**第三项支撑，是用一个真正有适用范围的不可辨识性论证替代经验上限语言。** 我用精确分数运算检查了一个构造。

两个世界都有 1000 行一列 0/1 数据，前五行均为 0，实际最小值为 0、最大值为 1。问题都是求整列均值，工具都返回 0.11。

| 世界 | 隐藏部分中的 1 的数量 | 真实均值 | 返回 0.11 的含义 |
|---|---:|---:|---|
| A | 110 | 0.11 | 正确 |
| B | 100 | 0.10 | 被乘以 1.10 |

前五行、形状、列名、最小值、最大值、问题和返回值完全一样。任何仅用这些观测的算法，在两种世界下得到的输入相同。在这一个专门构造且等概率的二点实验里，其期望判断正确率至多为一半。

这个构造可以证明某些合法条件下存在无法从当前观测区分的真假返回。它不能推出真实六张表的平均 AUROC 上限，也不能把 0o* 自动变成最优检测器。

更一般地，若已知 N、任意 k 个可见值的和 S_k，以及有效上下界 L、U，均值的一个确定性可行区间为

```text
I_k = [(S_k + (N-k)L)/N, (S_k + (N-k)U)/N]
```

在仅有这些约束时，未见行取不同合法值能达到相应端点。返回落在区间外可被排除，返回落在区间内通常还需要额外证据或分布假设。这是基础的部分识别推导，应明确使用的约束与先验。后续随机样本推断提供另一类、带抽样错误概率的决定。

这个理论支撑能帮助论文准确说明何时需要新增证据。将其包装成新的普遍不可能性定理，学术增量不足。若要更强理论贡献，还需研究特定扰动、取证策略与代价模型下的紧下界，并核查相关统计文献。

**更轻的备选方法是对残差建模。** 当前 P5 直接预测原始值，跨表数量级和尺度变化可能占去模型容量。可以先用 0d 或解析估计给出中心及尺度，让小模型学习标准化残差或区间修正，而非从头预测数值。建议先用轻量模型与简单统计校准比较。

这个候选也可能失败。若行中没有足够信息、基线中心偏差来自非代表性抽样，残差模型无法凭空恢复隐藏数据。必须按表留出、在同一支持集上比较，确认收益并非记住表或查询。它适合作为技术可行性不足时的一个备选，优先级低于证据获取与受控恢复实验。

**建议把接下来两周用于分阶段决策。**

1. 前两天完成原始证据核验的离线最小实现与诚实基线。复用现有任务统计逻辑，先核对缺失值、有效总体、数值边界和抽样假设。检查实际的成本、放行和保留判断曲线。
2. 同时准备六臂恢复实验的协议与格式检查。先验证完整字段污染、共享前缀和正确预算，不根据观察到的模型表现改变操纵。
3. 在离线方法有实用信号，或恢复设计能清晰区分候选解释后，再决定付费收集。新假设、排除条件、停止规则、主对照、错误预算和重复层级应先作独立协议提交。
4. 若方法有稳定的同预算增益，将核验方法作为论文主线，恢复实验解释为什么现有自报与自由重试不足。若方法无增益而恢复干预有清晰作用，考虑聚焦受控机制与评测条件。若两者均无增量，保留诚实的有限证据负结果，收窄论文目标。
5. 最后几天集中完成主图、主表、匿名正文和补充材料。四页正文应保留一条主线，避免把多个未完成方向堆叠成贡献列表。

候选标题可分别为 *Budgeted Verification of Numeric Tool Returns*，或 *How Error Feedback Changes Recovery from Corrupted Tool Returns*。二者的结论都需要新实验后再确定。

我最建议的下一步是先运行证据核验的离线可行性实验，并准备 180 条恢复 pilot。前者回答是否有可交付的技术改进，后者回答当前最有特点的行为现象能否在控制条件下成立。这比只扩大模型数量更直接地回应论文贡献问题。
