## 当前结论

两种模型的结果尚未提供稳定、跨模型复现的“相关 20 行优于随机 20 行”收益。不能据此断言 context 无效，也不能把 Qwen 的主效应为零写成方向反转。

| 模型 | Context | 接受正确返回 | 采用错误值 | 弃答：正确 / 错误条件（仅有效格式） |
|---|---|---:|---:|---|
| gemini-3.8-flash | head5 | 12/12 | 9/12 | 0 / 2 |
| gemini-3.8-flash | random20 | 12/12 | 7/12 | 0 / 4 |
| gemini-3.8-flash | matched20 | 11/12 | 5/12 | 0 / 5 |
| qwen3-8b | head5 | 12/12 | 10/12 | 0 / 2 |
| qwen3-8b | random20 | 10/12 | 9/12 | 2 / 3 |
| qwen3-8b | matched20 | 12/12 | 11/12 | 0 / 1 |

主对照是 matched20 − random20 在“接受正确返回 − 接受错误返回”上的配对差值。这个指标同时检查对正确返回的保留与对错误返回的抵抗，避免把全部拒绝当进步。

| 模型 | 主差值（百分点） | 描述性 95% 六表 bootstrap 区间 |
|---|---:|---|
| gemini-3.8-flash | +8.3 | [-16.7, +33.3] |
| qwen3-8b | +0.0 | [-33.3, +33.3] |

两组区间都覆盖零；12 个选定查询、6 个表簇、每条件一次完成，不能做等效性或普遍无效结论。Qwen 各表贡献有正有负，平均为零也不代表每个任务都不受 context 影响。Gemini 的主差值部分涉及格式失败，不能全部解释为语义核验收益。

Qwen 的随机 20 行条件有两个正确返回被判 uncertain；相关 20 行虽多接受了两个错误返回，也同时多接受了两个正确返回，所以主差值恰为零。原始错值接受次数与综合区分指标应分开解读。

## 数据和可比性核查

- 两模型 config 引用同一 canonical manifest hash：`7263b5dcd25ccf3c4463ffe6778243a3f953a153c55f0c493d9714cd0dc99983`，并引用相同 runner、传输和统计代码哈希。
- manifest 文件字节 SHA256 是 `d9c467dfb860fe37ae315708b2a49733f9c0bf84ec304ab140e4b67ce094999d`。它与 canonical JSON hash 算法口径不同，不是数据不一致。
- 两边都是 72 个唯一条件；Gemini 严格格式有效 67，Qwen 有效 72。逐条核对 unit、dataset、context、label、severity、答案正确性与错误值采用标记；复算所有已报告配对差值和完整有效配对敏感性，均一致。
- Gemini 可从 72 条 raw response 重跑 parser 核查；Qwen 入库 raw response 为 0 条。Qwen 的解析有效性、reason、请求/响应哈希只能暂按已有评分记录和 config 报告，尚未在此独立验证。缺档不等于运行失败，也不需要重跑。
- Qwen 需要补归档原始 responses/，并保留模型 checkpoint 与 vLLM 运行版本。当前 model 字段本身不足以固定完整运行环境。
- 不做 Gemini/Qwen 普遍鲁棒性排名：抽样参数不同，且只有一组任务与完成。

## 对 F10 addendum 的两处更正

1. “direction flips”只适用于某些次要点估计或原始错误接受次数；预注册主对照是 Gemini 正值、Qwen 零值，没有反向。
2. Qwen 记录是 64 个 accept、8 个 uncertain、0 个 reject；accept 的 confidence 均为 90，uncertain 均为 50。没有观察到 Gemini 那种 reject 同时 confidence≥95 的定义冲突。仅凭清洁/污染均值接近，不能声称 same scale-noncompliance。它是否校准、是否能识别错误仍未检验；因为缺 live 极端污染 sanity，AUROC 继续 withheld。

以上为对既有结果的复核，旧 findings 不重写，后面追加更正。独立 reviewer 子 agent 也指出上述两处问题；角色分离不代表统计独立的错误过程。

## 下一步：先区分证据不足与证据未被有效使用

**第一优先是无 API 成本的离线证据充分性 pilot，而非扩大同一组模型调用。** 以下是拟议分析计划，尚未实施；需要在产生新测量前单独提交协议。

1. 固定本轮 manifest 的同一查询、同一返回值、同一行索引。让统计核验器仅使用模型实际看到的样本和查询，不用 full-table truth、总体范围或未展示的筛选总体大小作特征。全表真值只用于评价。
2. 复用 `zeroparam.py` 的 0a、`template_stat`、`bootstrap_0d` 和 interval scoring，不再另写一套同名信号。对均值任务，比较返回值与样本估计/区间；固定 bootstrap 配置与阈值，不能看结果后挑阈值。Bootstrap 区间是受测估计方法，不默认提供有限样本错误率保证。
3. 先检查已知极端错误的 sanity（正确均值乘/除 1000）。失败或无覆盖的方法照实标为 withheld。head5/random20 中筛选后没有有效目标行时是“无法评分”，不能悄悄填成正常或只保留有利任务。
4. 报告每个 context 的有效筛选行数、评分覆盖、clean 误拒、错误放行、弃权、按表和严重度切片；检测 AUROC 只在 sanity 过门槛的条件下报告，主统计按表等权并保留共同任务支持集。样本小，结论仍标 exploratory。

这项实验回答的是：同样这些行，已有统计方法是否能提取出比当前模型判断更可靠的区分信号？它不证明某个方法最优，也不把未成功检测等同于信息论上不可能。

| 离线结果 | 对研究方向的影响 |
|---|---|
| 统计方法能区分，clean 误拒也可控，而模型仍常接受错误 | 支持进一步检验模型提取/使用证据的问题。下一轮比较原始样本与由同一样本计算的统计证据摘要。 |
| 统计方法也分不开，或 clean 误拒很高 | 先改证据预算、抽样和任务设计。继续微调 confidence 提示不能解决已展示证据不足的问题。 |
| 方法连极端 sanity 都失败或覆盖极低 | 先修测量与适用范围，暂停性能或机制主张。 |

**只有离线结果值得继续，才进入新一轮 LLM 实验。** 使用新生成或数值经过变换的表，覆盖多个独立表与抽样种子；仅改列名不足以排除数据记忆。先锁定生成分布、任务、污染、clean 控制、sanity、输出 schema 和评分。

建议核心对照是“同样 20 行原始证据”与“同样 20 行加可验证的样本统计摘要”，后者只变换已有证据，不加入全表真值。保留直接统计核验器作为基线，分别衡量错误接受、clean 误拒和弃答，并按查询配对；不要把多个模型回答或重复行抽样当独立表。confidence 如继续测量，应单独明确为工具值正确的概率，先做独立格式/语义检查，不事后翻转已有分数。

这是一项待检验的机制实验或工程改进，不自动构成新算法。若要主张技术创新，还需证明相对已有核验基线的收益和成本优势，并另做近邻文献核对。

## 论文推进建议

保留当前结果作为有边界的探索性证据：在这些选定数值任务上，显式要求审计并展示相关样本，尚未显示跨模型稳定的主对照收益。它能支持研究动机和局限讨论，不能单独证明“模型不利用证据”“更多 context 无效”或“工具返回核验存在通用信息上限”。

优先完成一次能区分两种解释的离线 pilot，再决定将论文重心放在证据预算/采样，还是模型如何消费统计证据。现在不建议仅为确认 context 收益而扩大 T_max 自由 agent 实验；自由 agent 的大 context 行为是另一个问题，需要单独协议。现有材料可以继续组织为实证 workshop 稿，但新颖性和可录用性不能由本轮结果或旧审稿备忘录中的录用概率推算。
